# MVP: แผนที่เอกสารขัดแย้ง (Conflict Map)

เดโมนี้ทำขั้น **Understand → Connect → Reason** ของ AI Audit Concierge บนข้อมูลสมมติ (synthetic) ทั้งหมด
ระบบอ่านเอกสารของ engagement หนึ่งชุด จับคู่เป็นธุรกรรม PO → ใบรับของ → Invoice → รายการโอน
แล้วชี้จุดที่เอกสาร **ขัดแย้งกัน** พร้อมหลักฐานที่อ้างข้อความจริงจากไฟล์ต้นฉบับ ผู้สอบบัญชีเป็นผู้ตัดสินเสมอ

## โครงสร้าง

| โฟลเดอร์ | ภาษา | หน้าที่ |
| --- | --- | --- |
| `pipeline/` | Python | อ่านไฟล์ทุกรูปแบบ, จับคู่เอกสาร, ตรวจขัดแย้ง 8 ประเภท, เขียน `conflict_map.json` |
| `web/` | React + TSX (Vite) | หน้า **ควรตรวจ** แบบ 3 ช่อง (รายการ · กระดาษทำการ · เอกสารต้นฉบับ), **รอจับคู่**, **ภาพรวม**, ลงนามผู้จัดทำ/ผู้สอบทาน, **รายงาน** (PDF + Excel) |
| `worker/` | JavaScript (Cloudflare Worker) | เสิร์ฟเว็บ + `POST /api/ask` ถามตอบผ่าน Gemini จากผลการตรวจเท่านั้น + `/api/trail` เก็บ Audit Trail ใน D1 + ล็อกอิน / Engagement / อัปโหลดไฟล์เข้ารหัส / ลบไฟล์หลังปิดงาน |
| `pipeline/auditconcierge/server.py` | Python (container บน Render ฟรี) | รับงานจาก Worker ดึงไฟล์ที่อัปโหลด รัน pipeline แล้วส่งผลกลับ ไม่เก็บอะไรไว้ |

## หลักการที่โค้ดบังคับใช้

- **โค้ดเป็นผู้ตัดสินว่าขัดแย้ง** ไม่ใช่ AI: ทุกค่าที่ใช้ต้องมีข้อความต้นฉบับ (quote) ที่ตรวจแล้วว่าอยู่ในไฟล์จริง
- ทุกจุดมีสถานะ **"ควรตรวจ"** ไม่ใช่ข้อสรุปว่าผิด และต้องใส่เหตุผลก่อนกด เป็น/ไม่เป็นประเด็น
- **จับคู่ 3 ระดับ:** จากเลขอ้างอิง (sure) / โดยอนุมาน (likely, ลดความเสี่ยงลงหนึ่งขั้นและติดป้าย) / **รอจับคู่** (มีหลายตัวเลือก ไม่นำไปตรวจจนกว่าผู้สอบบัญชียืนยัน)
- **OCR อ่านไม่ชัด** (ความมั่นใจ < 60) จะติดป้าย "อ่านไม่ชัด" และไม่ถูกใช้ยกประเด็น พร้อมภาพตัดจากสแกนให้เทียบ
- **ไม่พบ ≠ ไม่มี:** ก่อนยก MISSING_LINK ระบบค้นข้อความเต็มทุกไฟล์ก่อน
- กฎบริษัท (Remember) ใช้ได้เฉพาะเมื่อพบข้อความของกฎในเอกสารนโยบายจริง
- **ดูต้นฉบับแบบ DataSnipper:** pipeline เรนเดอร์หน้า PDF/สแกนเป็นภาพ (`pages/`) พร้อมพิกัดของแต่ละค่า เว็บตีกรอบ ✓ ตรงบรรทัดที่ค่ามาจากไหน ส่วนไฟล์ CSV/XLSX แสดงเป็นตารางและไฮไลต์แถว/ช่อง โดยใช้เฉพาะข้อความที่อ้างไว้แล้ว บรรทัดที่หน้าตาเหมือนเลขบัญชีจะถูกถมดำก่อนบันทึกภาพ
- **ลงนามกระดาษทำการ:** ผู้จัดทำใส่ผลและเหตุผล แล้วผู้สอบทาน (ชื่อย่อต้องไม่ซ้ำกับผู้จัดทำ) ลงนามต่อ
- **Audit Trail บน server:** ทุกการลงนาม การแก้ไข การยกเลิกสอบทาน และการยืนยันคู่ ถูก *เพิ่ม* เป็นแถวใหม่ใน D1 ไม่มีการแก้หรือลบ (ดูหัวข้อ Audit Trail ด้านล่าง)
- **เลขบัญชีธนาคาร** ถูกแปลงเป็น token (salted SHA-256) ตั้งแต่ตอนอ่านไฟล์ ผลลัพธ์แสดงแบบปิดบัง เช่น `xxx-x-xx321-0` (มีเทสต์ตรวจว่าไม่มีเลขบัญชีเต็มหลุดออกไป)
- **รายงานสรุปแบบกระดาษทำการ** (แท็บ "รายงาน", โค้ดอยู่ใน `web/src/report/`): มี 2 ฉบับ
  - **ฉบับ Manager:** ทุกรายการที่ควรตรวจ พร้อมหลักฐาน (เอกสาร · ไฟล์ · ตำแหน่ง · ข้อความต้นฉบับ) ผลการพิจารณา เหตุผล และผู้จัดทำ/ผู้สอบทานพร้อมวันเวลา รวมถึงรายการรอจับคู่และขอบเขตข้อมูล
  - **ฉบับส่งลูกค้า:** เฉพาะรายการที่ผู้สอบทานลงนามแล้วว่า "เป็นประเด็น" พร้อมหลักฐานและคำถามที่ขอคำชี้แจง ไม่มีเหตุผลภายในของทีม (รายการที่ยังไม่สอบทานไม่ใช่ข้อสรุป จึงไม่ออกไปนอกสำนักงาน)
  - **บันทึก PDF** ใช้การพิมพ์ของเบราว์เซอร์ (เลือก "Save as PDF") ภาษาไทยแสดงด้วยฟอนต์ของเครื่อง มีช่องลงนามจัดทำ/สอบทาน/อนุมัติ (Manager)
  - **Export Excel** เป็นไฟล์ `.xlsx` จริงหลายชีต: สรุป · รายการควรตรวจ (หรือ ประเด็น) · หลักฐาน · รอจับคู่ · ไฟล์ (SHA-256) ตรึงแถวหัวตารางและเปิดตัวกรองไว้ สร้างในเบราว์เซอร์ทั้งหมด ไม่ส่งข้อมูลออกไปไหน
  - **Export Word** เป็นไฟล์ `.docx` เนื้อหาเดียวกับรายงานที่พิมพ์ (ช่องลงนาม · สรุป · รายการพร้อมหลักฐานและผลการพิจารณา · รอจับคู่ · ขอบเขตข้อมูล) ขนาด A4 ฟอนต์ Tahoma มีเลขหน้าและข้อความ "ข้อมูลลับ" ท้ายกระดาษ ใช้แก้ไขต่อในแม่แบบกระดาษทำการของสำนักงาน ฉบับส่งลูกค้ามีเฉพาะประเด็นที่สอบทานแล้ว สร้างในเบราว์เซอร์ทั้งหมดเช่นกัน
- AI ถามตอบเห็นเฉพาะผลการตรวจ ไม่เห็นเอกสารดิบ: เดโมสาธารณะไม่มีอัปโหลด ส่วน Engagement ถาม AI ได้เฉพาะสมาชิกทีมและเฉพาะ Engagement ที่เป็นข้อมูลสมมติ

## Cross-check FN/FP (พลาด / ยกเกิน)

- **ให้คะแนนกับเฉลย:** `python -m auditconcierge.crosscheck <โฟลเดอร์> [expected.json]` รัน pipeline แล้วนับ TP / FN (ควรจับแต่พลาด) / FP (ยกเกิน) ต่อประเภท พร้อม recall/precision, ธุรกรรมสะอาดที่ถูกยก และรายการรอจับคู่ที่ต่างจากเฉลย (exit 1 ถ้ามี FN/FP) ผลปัจจุบัน TG Company 12/12 และชุดฟู้ดส์แช่แข็ง 9/9 ไม่มี FP
- **ชุดที่สอง:** `pipeline/samples/frozen_foods.py` สร้างชุดอัปโหลดทดสอบ (บริษัท สมมติฟู้ดส์แช่แข็ง, 9 จุดที่ฝังไว้) ได้ทั้งชุด `python samples/frozen_foods.py <out>` และเรียกจากเทสต์เพื่อแก้ข้อมูลทีละจุด
- **Seeded-error test** (`tests/test_seeded_errors.py`): แก้ข้อมูลหนึ่งอย่างแล้วรันใหม่ ฝั่ง FN ทุกกฎต้องยกจุดใหม่ที่ถูกต้องหนึ่งจุดพอดี (15 แบบ เช่น ยอดเกิน tolerance, บัญชีปลายทางเปลี่ยน, จ่ายซ้ำ, PO หาย, ราคาเกินสัญญา, จ่ายเกินเครดิต, เกินวงเงิน, ชื่อคู่สัญญาต่าง) ฝั่ง FP ต้องไม่ยกอะไรเลยเมื่อเป็น near miss (12 แบบ เช่น ต่างพอดี tolerance, เท่ากับเกณฑ์อนุมัติ 100,000 ฿, จ่ายวันสุดท้ายของเครดิต, ยอดสะสมเท่าวงเงิน, จับคู่โดยอนุมาน)
- **ช่องโหว่ที่รู้แล้ว** เป็น xfail แบบ strict (ถ้าแก้ได้ เทสต์จะแดงให้มาอัปเดตรายการนี้): Invoice ซ้ำที่ออกเลขใหม่คนละวันแต่อ้าง PO เดิม, การแตก PO ให้ต่ำกว่าเกณฑ์อนุมัติ
- **จุดที่ตรวจไม่ได้** (`coverage.skipped_checks`, แสดงในแท็บภาพรวม): ทุกเอกสารที่กฎถูกข้ามพร้อมเหตุผล เช่น ช่องอ่านไม่ชัด, รอจับคู่, ระบุ vendor ไม่ได้, รายการโอนที่ไม่มี Invoice, PO ที่มีใบรับของแต่ยังไม่มี Invoice, กฎที่หาข้อความในนโยบายไม่พบ เพื่อให้ผู้ตรวจเห็นว่า "ไม่มีประเด็น" ≠ "ไม่มีปัญหา"
- ค่าที่ข้อความอ้างอิงหาไม่พบในไฟล์จะไม่ถูกใช้ตรวจเลย (`Record.v`) และชื่อคู่สัญญาที่ PDF ตัดขึ้นบรรทัดใหม่อ่านได้แล้ว (ก่อนหน้านี้การตรวจคู่สัญญาถูกข้ามเงียบๆ พบจาก seeded-error test)

## อ่านเอกสารด้วย LLM (แทน template)

ไฟล์ PDF และสแกนอ่านด้วย Gemini ได้ (`pipeline/auditconcierge/extract_llm.py`) จึงรับ Invoice/สัญญาที่หน้าตาต่างจากตัวอย่างได้ เช่น ภาษาอังกฤษ วันที่แบบ พ.ศ. หรือ "12 ก.พ. 2569" โดยยังให้ **โค้ดเป็นผู้ตัดสินค่า**:

- ก่อนส่งให้โมเดล ตัวเลขที่หน้าตาเหมือนเลขบัญชี/เบอร์โทร (10–12 หลัก) ถูกปิดบังเหลือ 4 หลักท้าย ส่วนเลขผู้เสียภาษี วันที่ และยอดเงินยังอ่านได้
- โมเดลทำแค่ชี้ว่าค่าอยู่บรรทัดไหน แล้วคัดลอกตัวอักษรของค่า (`raw`) กับข้อความสั้นๆ (`quote`) มาตรงตัว ห้ามคำนวณหรือแปลงรูปแบบ ตารางราคาในสัญญาต้องมีชื่อสินค้าและราคาอยู่บรรทัดเดียวกัน
- โค้ดตรวจว่า `raw` และ `quote` อยู่ในบรรทัดนั้นจริง (เทียบแบบ normalise ไทย) แล้วแปลงเป็นค่าเอง (ยอดเงิน, วันที่ พ.ศ./ค.ศ./ชื่อเดือนไทย, จำนวนวัน, เลขผู้เสียภาษี 13 หลัก)
- ค่าที่หาไม่เจอในเอกสารเป็น "ไม่ได้ตรวจยืนยัน" และค่าที่แปลงไม่ได้ (เช่น OCR อ่านเลขที่เป็นอักษรไทย) เป็น "อ่านไม่ชัด" ทั้งสองแบบไม่ถูกใช้ยกประเด็น
- ลองโมเดลตามลำดับใน `GEMINI_MODELS` (ค่าเริ่มต้น Gemini 3.5/3.1 Flash-Lite → 3.8 Flash → 2.5 Flash → Gemma 4) ตัวที่โควตาเต็มหรือไม่มีให้ใช้จะข้ามไปตลอดรอบ ถ้า key ผิดหรือไม่มีโมเดลไหนตอบ ไฟล์นั้นใช้ template เดิม และ `conflict_map.json` บอกไว้ใน `extraction`

```bash
cd pipeline
GEMINI_API_KEY=... python -m auditconcierge samples/tg_company --out ../web/public/data            # auto: มี key ใช้ LLM
python -m auditconcierge samples/tg_company --out ../web/public/data --extractor template          # ออฟไลน์
```

เทสต์ใช้ template เป็นหลัก และรันชุดเฉลยเดิมซ้ำผ่านเส้นทาง LLM ด้วยโมเดลจำลอง (`tests/fake_llm.py`) จึงไม่ต้องใช้ key หรืออินเทอร์เน็ต ใช้ได้กับข้อมูลสมมติเท่านั้นจนกว่าจะเปลี่ยนไปใช้ผู้ให้บริการที่ไม่เก็บข้อมูลก่อน pilot

## วิธีรัน

```bash
# 1) pipeline (ต้องมี tesseract-ocr และ tesseract-ocr-tha)
sudo apt-get install -y tesseract-ocr tesseract-ocr-tha fonts-tlwg-loma-otf
cd pipeline
pip install -r requirements.txt
python -m pytest -q                                   # เทสต์เทียบกับเฉลย
python -m auditconcierge samples/tg_company --out ../web/public/data

# (ถ้าต้องการสร้างเอกสารตัวอย่างใหม่: ต้องมีฟอนต์ fonts-tlwg-loma-otf)
python samples/generate.py

# 2) เว็บ
cd ../web && npm install && npm run dev               # http://localhost:5173

# 3) Worker (ถามตอบ) — อีกหน้าต่างหนึ่ง
cd ../worker && npm install && npm test
npm run dev                                           # http://localhost:8787 (build เว็บให้เอง แล้วเสิร์ฟทั้งเว็บและ /api/ask)
```

ถ้าไม่ได้ตั้ง `GEMINI_API_KEY` ช่องถามตอบยังใช้ได้ โดยตอบด้วยการค้นคำจากรายการที่ควรตรวจแทน

```bash
npx wrangler secret put GEMINI_API_KEY    # key จาก Google AI Studio (free tier) เก็บไว้ที่ Worker เท่านั้น
npx wrangler deploy                       # build เว็บ (web/dist) ให้เองก่อน แล้ว deploy ทั้งเว็บและ API เป็น Worker เดียว
```

- ถ้าเชื่อม repo กับ Cloudflare (Workers Builds): ตั้ง Root directory เป็น `/` และ Deploy command เป็น `npx wrangler deploy` ไม่ต้องใส่ Build command เพราะ `wrangler.jsonc` สั่ง build ให้แล้ว
- **ห้ามอัปโหลดโฟลเดอร์ `web/` ตรงๆ** (เช่นลากไฟล์ขึ้น dashboard) เพราะเป็นซอร์สที่ยังไม่ build เบราว์เซอร์จะเปิด `.tsx` ไม่ได้และขึ้นจอขาว ถ้าจะอัปโหลดเอง ให้ใช้ `web/dist` หลังรัน `npm run build` ใน `web/`

- โมเดลถามตอบตั้งไว้ที่ `GEMINI_MODELS` ใน `wrangler.jsonc` เป็นรายชื่อเรียงลำดับ คั่นด้วยจุลภาค ตอนนี้เริ่มที่ Gemma 4 26B → Gemma 4 31B → Gemini 3.5/3.1 Flash-Lite → Gemini 3.8 Flash → Gemini 2.5 Flash ถ้าโมเดลไหนโควตาเต็ม (429), เกินขนาด token, ไม่มีให้ใช้ (404), ล่ม หรือช้าเกิน 20 วินาที Worker จะลองตัวถัดไปเอง และพักโมเดลที่เต็มไว้ 1 นาที ใช้ key เดิมทั้งหมด คำตอบจะบอกว่าตอบโดยโมเดลไหน
- จำกัดการถามต่อ IP ต่อวัน (`DAILY_LIMIT_PER_IP`, ค่าเริ่มต้น 20) และรวมทั้งวัน (`DAILY_LIMIT_TOTAL`, 300) ใน `wrangler.jsonc` ที่ root
- ถ้าต้องการให้ limit แม่นทุก instance ให้ผูก KV namespace ชื่อ `RATE` (ฟรี) ไม่ผูกก็ใช้ได้แต่จะนับแยกตาม instance
- หรือเผยแพร่เฉพาะ `web/dist` บน GitHub Pages / Cloudflare Pages ก็ได้ (ไม่มีช่องถามตอบ)

## Audit Trail (D1, ฟรี)

การตัดสินของผู้สอบบัญชีเก็บที่ Worker ในฐานข้อมูล Cloudflare D1 ชื่อ `auditpal-trail` (binding `AUDIT_DB`, สร้างไว้แล้วใน APAC และใส่ id ไว้ใน `wrangler.jsonc` แล้ว)
deploy ครั้งถัดไปใช้ได้ทันที Worker สร้างตารางให้เองตอนใช้ครั้งแรก ไม่ต้องรัน migration

| ส่วน | ทำอะไร |
| --- | --- |
| `GET /api/trail?ws=&run=` | คืนประวัติทั้งหมด สถานะปัจจุบันที่ได้จากการเล่นประวัติซ้ำ และ `chain_ok` |
| `POST /api/trail` | เพิ่มเหตุการณ์ 1 รายการ: `prepare` (ผล + เหตุผล ≥ 5 ตัวอักษร), `review`, `unreview`, `reopen`, `pair` |

- **เพิ่มได้อย่างเดียว:** โค้ดใช้แค่ `INSERT` และ trigger ใน SQLite ปฏิเสธ `UPDATE`/`DELETE` ทุกครั้ง การกด "แก้ไข" คือการเพิ่มเหตุการณ์ `reopen` ประวัติเดิมยังอยู่
- **สายแฮช:** แต่ละแถวเก็บ SHA-256 ของแถวก่อนหน้า ถ้ามีคนแก้แถวตรงๆ (เช่นผ่าน dashboard) `chain_ok` จะเป็น false และหน้าเว็บขึ้นเตือน
- **server เป็นผู้ตัดสิน:** เวลาบันทึกมาจาก server, ผู้สอบทานต้องไม่ใช่ผู้จัดทำ, ต้องลงนามผู้จัดทำก่อนสอบทาน, รายการต้องมีอยู่ใน `conflict_map.json` รอบเดียวกัน (`run_id`)
- **อ้างหลักฐาน:** server คัดลอก doc / file / locator / SHA-256 ของไฟล์จากผลการตรวจที่เผยแพร่ ไม่รับจากเบราว์เซอร์
- **เดโมปลอดภัย:** ไม่มีอัปโหลด, body ≤ 2 KB, จำกัดการเขียนต่อ IP ต่อวัน (`TRAIL_WRITES_PER_IP`, 200), แต่ละเบราว์เซอร์ได้ workspace ของตัวเอง ถ้าต้องการให้ผู้จัดทำกับผู้สอบทานเห็นชุดเดียวกัน เปิดลิงก์ `?ws=<ชื่อ>` เดียวกัน (ตัวพิมพ์เล็ก ตัวเลข `-` ยาว 4–40)
- ปุ่ม **Audit Trail** บนแถบบน export ประวัติทั้งหมดเป็น CSV พร้อมแฮช
- ถ้าไม่ได้ผูก D1 (เช่นรัน `npm run dev` ของเว็บอย่างเดียว) หน้าเว็บจะเก็บประวัติแบบเดียวกันในเบราว์เซอร์แทนและบอกไว้ใต้ช่องลงนาม

ถ้าจะสร้างฐานข้อมูลใหม่เอง (เช่นบัญชี Cloudflare อื่น): `npx wrangler d1 create auditpal-trail --location apac` แล้วใส่ id ที่ได้ใน `wrangler.jsonc`
ดูข้อมูลได้ด้วย `npx wrangler d1 execute auditpal-trail --remote --command "SELECT seq, at, actor, action, target, value FROM trail_events ORDER BY at DESC LIMIT 20"`
รันในเครื่อง `npm run dev` ใน `worker/` ใช้ D1 จำลองในเครื่อง (`.wrangler/`) ไม่แตะฐานข้อมูลจริง

## ใช้งานจริง: ล็อกอิน · Engagement · อัปโหลด (ทดลองกับข้อมูลสมมติ)

ขั้นตอน deploy และค่าที่ต้องตั้งอยู่ใน [`docs/deploy-pipeline.md`](deploy-pipeline.md) · บัญชีทดลองและเส้นทาง demo สำหรับผู้ใช้ภายนอกอยู่ใน [`docs/demo.md`](demo.md)

```
เบราว์เซอร์ ──(cookie, x-ac-csrf)──▶ Cloudflare Worker ──▶ D1 auditpal-trail  (ผู้ใช้, Engagement, ทีม, Audit Trail, บันทึกการใช้งาน)
                                         │            └──▶ D1 auditpal-files  (ไฟล์ + ผลการตรวจ เข้ารหัส AES-256-GCM แยกกุญแจต่อ Engagement)
                                         │ งาน (HMAC)
                                         ▼
                              Render (Docker, Singapore): Python + Tesseract
                              ดึงไฟล์ทีละไฟล์ (HMAC) → build() → ส่งภาพหน้าเอกสาร + conflict_map.json กลับ → ลบโฟลเดอร์ชั่วคราว
```

- **ล็อกอิน:** ไม่มีสมัครเอง บัญชีแรก (ผู้ดูแลระบบ) สร้างด้วย `SETUP_TOKEN` จากนั้นผู้ดูแลสร้างบัญชีให้ทีม ได้รหัสผ่านใช้ครั้งเดียวและต้องเปลี่ยนตอนเข้าครั้งแรก รหัสผ่านเก็บเป็น PBKDF2-SHA256, session เป็น cookie HttpOnly/Secure/SameSite=Strict อายุ 12 ชม., ล็อกอินผิด 8 ครั้งใน 15 นาทีถูกพัก
- **บทบาทต่อ Engagement:** ผู้จัดทำ (อัปโหลด ประมวลผล ลงนามผู้จัดทำ ยืนยันคู่) · ผู้สอบทาน (+ ลงนามสอบทาน) · Manager (+ ทีม, tolerance/materiality, ปิดงาน) ผู้ลงนามใน Audit Trail คือชื่อย่อของบัญชีที่ล็อกอิน (server ไม่รับชื่อที่พิมพ์) และผู้สอบทานต้องไม่ใช่ผู้จัดทำรายการเดียวกัน
- **แยกข้อมูลต่อ Engagement:** ทุก API ตรวจว่าผู้ใช้อยู่ในทีม (ผู้ดูแลระบบก็ไม่เห็นถ้าไม่อยู่ในทีม) ไฟล์เข้ารหัสด้วยกุญแจที่ derive เฉพาะ Engagement นั้น (HKDF จาก secret `FILES_KEY`) และผูก path ไว้ ย้ายข้อมูลข้าม Engagement แล้วถอดรหัสไม่ได้ เครื่องประมวลผลดึงได้เฉพาะไฟล์ของรอบที่กำลังรันอยู่
- **รับไฟล์:** PDF, PNG/JPG/TIFF, CSV, XLSX และ `remember.json` (กฎของบริษัท) ไม่เกิน 10 MB/ไฟล์ 200 ไฟล์/Engagement ตรวจว่าเนื้อไฟล์ตรงกับนามสกุล ชื่อซ้ำ = เวอร์ชันใหม่ (ลบของเดิม)
- **ปิดงานและลบไฟล์:** Manager กดปิดงาน → แก้ไขไม่ได้ cron ของ Worker (ทุกวัน 03:00 UTC) ลบไฟล์ดิบและภาพหน้าเอกสาร/ภาพตัดจากสแกน เมื่อครบ `RETENTION_DAYS` (90) วันหลังปิด เก็บ `conflict_map.json` (กระดาษทำการพร้อม quote) และ Audit Trail ไว้ ทุกการกระทำ (อัปโหลด ดาวน์โหลด รัน ลบ ปิดงาน) อยู่ใน **บันทึกการใช้งาน** ที่เพิ่มได้อย่างเดียว
- **ข้อมูลสมมติเท่านั้นตอนนี้:** `ALLOW_REAL_DATA` = `false` ทุก Engagement จะเป็นข้อมูลสมมติ จนกว่าจะเปลี่ยนผู้ให้บริการ AI และ region ตามที่ตัดสินไว้
- ทดสอบครบวงจรในเครื่อง (wrangler dev + server.py + Chromium): อัปโหลดชุด TG Company 20 ไฟล์ผ่านหน้าเว็บ → ประมวลผล → พบ 12/12 จุดเหมือนรันจาก CLI → ผู้จัดทำกับผู้สอบทานคนละบัญชีลงนาม → ปิดงาน

## ข้อจำกัดของ MVP

- ค่าเริ่มต้นอ่านเอกสารด้วย **template + regex** ที่ตรงกับเอกสารตัวอย่าง เส้นทาง LLM (หัวข้อ "อ่านเอกสารด้วย LLM") เปิดเมื่อมี key และใช้ได้กับข้อมูลสมมติเท่านั้น
- การตรวจสัญญาครอบคลุม เครดิต (วัน), ราคาต่อหน่วยตามตารางราคา, อายุสัญญา, วงเงินรวม, การจ่ายเกินเครดิต และชื่อคู่สัญญา ยังไม่ตรวจส่วนลด/ค่าปรับ, จำนวนขั้นต่ำ และยังไม่มีเส้นทาง LLM เทียบข้อความสัญญาทั่วไป ราคาต่อหน่วยเทียบเฉพาะ Invoice ที่มีรายการเดียวและชื่อสินค้าตรงกับตารางราคา
- เดโมสาธารณะ (`#/demo`) ยังใช้ชื่อย่อที่พิมพ์เอง ส่วน Engagement ใช้บัญชีที่ล็อกอิน การยืนยันคู่ยังไม่รันตรวจใหม่ (กดประมวลผลใหม่เอง)
- เครื่องประมวลผลบน server เรียก pipeline แบบ template (ยังไม่เปิดเส้นทาง LLM) เอกสารที่อัปโหลดจึงต้องหน้าตาใกล้ template ของชุดตัวอย่าง ไฟล์ที่อ่านไม่ได้จะขึ้นใน "อ่านไม่ได้" ไม่ถูกเดา
- เครื่องประมวลผลฟรีบน Render อยู่สิงคโปร์ (ยังไม่ใช่ region ในไทย) หลับเมื่อว่าง 15 นาที กดประมวลผลครั้งแรกรอราว 1 นาที, Workers Free จำกัด CPU 10 ms/คำขอ ถ้าล็อกอินหรืออัปโหลดไฟล์ใหญ่ขึ้น error เรื่อง CPU ให้ใช้ Workers Paid ($5/เดือน) หรือลด `PASSWORD_ITERATIONS`
- ยังไม่มี MFA / SSO และยังไม่มีหน้าลบ Engagement ทั้งชุดก่อนครบ 90 วัน
- Gemini ใช้ได้กับ **ข้อมูลสมมติเท่านั้น** ต้องเปลี่ยนผู้ให้บริการ/สัญญาข้อมูลก่อน pilot กับข้อมูลจริง และใช้ cloud region ในไทยตามที่ออกแบบไว้
- ผล OCR ขึ้นกับเวอร์ชัน Tesseract (ทดสอบกับ 5.3.4) ไฟล์สแกนตัวอย่างอ่านเลขที่ Invoice ผิดโดยตั้งใจให้เห็นว่าระบบรับมืออย่างไร
