# MVP: แผนที่เอกสารขัดแย้ง (Conflict Map)

เดโมนี้ทำขั้น **Understand → Connect → Reason** ของ AI Audit Concierge บนข้อมูลสมมติ (synthetic) ทั้งหมด
ระบบอ่านเอกสารของ engagement หนึ่งชุด จับคู่เป็นธุรกรรม PO → ใบรับของ → Invoice → รายการโอน
แล้วชี้จุดที่เอกสาร **ขัดแย้งกัน** พร้อมหลักฐานที่อ้างข้อความจริงจากไฟล์ต้นฉบับ ผู้สอบบัญชีเป็นผู้ตัดสินเสมอ

## โครงสร้าง

| โฟลเดอร์ | ภาษา | หน้าที่ |
| --- | --- | --- |
| `pipeline/` | Python | อ่านไฟล์ทุกรูปแบบ, จับคู่เอกสาร, ตรวจขัดแย้ง 7 ประเภท, เขียน `conflict_map.json` |
| `web/` | React + TSX (Vite) | หน้า **ควรตรวจ** แบบ 3 ช่อง (รายการ · กระดาษทำการ · เอกสารต้นฉบับ), **รอจับคู่**, **ภาพรวม**, ลงนามผู้จัดทำ/ผู้สอบทาน, Export Excel |
| `worker/` | JavaScript (Cloudflare Worker) | เสิร์ฟเว็บ + `POST /api/ask` ถามตอบผ่าน Gemini จากผลการตรวจเท่านั้น + `/api/trail` เก็บ Audit Trail ใน D1 |

## หลักการที่โค้ดบังคับใช้

- **โค้ดเป็นผู้ตัดสินว่าขัดแย้ง** ไม่ใช่ AI: ทุกค่าที่ใช้ต้องมีข้อความต้นฉบับ (quote) ที่ตรวจแล้วว่าอยู่ในไฟล์จริง
- ทุกจุดมีสถานะ **"ควรตรวจ"** ไม่ใช่ข้อสรุปว่าผิด และต้องใส่เหตุผลก่อนกด เป็น/ไม่เป็นประเด็น
- **จับคู่ 3 ระดับ:** จากเลขอ้างอิง (sure) / โดยอนุมาน (likely, ลดความเสี่ยงลงหนึ่งขั้นและติดป้าย) / **รอจับคู่** (มีหลายตัวเลือก ไม่นำไปตรวจจนกว่าผู้สอบบัญชียืนยัน)
- **OCR อ่านไม่ชัด** (ความมั่นใจ < 60) จะติดป้าย "อ่านไม่ชัด" และไม่ถูกใช้ยกประเด็น พร้อมภาพตัดจากสแกนให้เทียบ
- **ไม่พบ ≠ ไม่มี:** ก่อนยก MISSING_LINK ระบบค้นข้อความเต็มทุกไฟล์ก่อน
- กฎบริษัท (Remember) ใช้ได้เฉพาะเมื่อพบข้อความของกฎในเอกสารนโยบายจริง
- **ดูต้นฉบับแบบ DataSnipper:** pipeline เรนเดอร์หน้า PDF/สแกนเป็นภาพ (`pages/`) พร้อมพิกัดของแต่ละค่า เว็บตีกรอบ ✓ ตรงบรรทัดที่ค่ามาจากไหน ส่วนไฟล์ CSV/XLSX แสดงเป็นตารางและไฮไลต์แถว/ช่อง โดยใช้เฉพาะข้อความที่อ้างไว้แล้ว บรรทัดที่หน้าตาเหมือนเลขบัญชีจะถูกถมดำก่อนบันทึกภาพ
- **ลงนามกระดาษทำการ:** ผู้จัดทำใส่ผลและเหตุผล แล้วผู้สอบทาน (ชื่อย่อต้องไม่ซ้ำกับผู้จัดทำ) ลงนามต่อ
- **Audit Trail บน server:** ทุกการลงนาม การแก้ไข การยกเลิกสอบทาน และการยืนยันคู่ ถูก *เพิ่ม* เป็นแถวใหม่ใน D1 ไม่มีการแก้หรือลบ (ดูหัวข้อ Audit Trail ด้านล่าง)
- **เลขบัญชีธนาคาร** ถูกแปลงเป็น token (salted SHA-256) ตั้งแต่ตอนอ่านไฟล์ ผลลัพธ์แสดงแบบปิดบัง เช่น `xxx-x-xx321-0` (มีเทสต์ตรวจว่าไม่มีเลขบัญชีเต็มหลุดออกไป)
- Worker ไม่มีช่องอัปโหลด และ AI เห็นเฉพาะผลการตรวจที่เผยแพร่ ไม่เห็นเอกสารดิบ

## ประเภทความขัดแย้ง

| ประเภท | ตัวอย่างในชุดข้อมูลสมมติ |
| --- | --- |
| VALUE_MISMATCH | PO-2026-002 120,000 ฿ แต่ INV-TG-102 150,000 ฿ |
| PARTY_MISMATCH | INV-TG-105 โอนเข้าบัญชีที่ไม่ใช่ของ vendor ใน Vendor master |
| DATE_ORDER | INV-BS-201 จ่ายเงินก่อนวันที่ใน Invoice |
| MISSING_LINK | INV-NS-301 ไม่มี PO และใบรับของ |
| POLICY_BREACH | PO-2026-002 เกิน 100,000 ฿ แต่ไม่ได้อนุมัติโดย Manager (กฎ R1) |
| DUPLICATE | INV-BS-205 มีทั้ง PDF และไฟล์สแกน และถูกโอนจ่าย 2 ครั้ง |
| TEXT_CONFLICT | สัญญาเครดิต 60 วัน แต่ INV-TG-102 ระบุ 30 วัน |

และ INV-TG-110 เข้าคิว **รอจับคู่** เพราะเข้าได้กับทั้ง PO-2026-007 และ PO-2026-008
ผลปัจจุบัน: พบครบ 7/7 จุดที่ฝังไว้, ไม่มีจุดเกิน, รอจับคู่ 1 รายการ (เทียบกับ `pipeline/samples/tg_company/expected.json`)

## วิธีรัน

```bash
# 1) pipeline (ต้องมี tesseract-ocr และ tesseract-ocr-tha)
sudo apt-get install -y tesseract-ocr tesseract-ocr-tha
cd pipeline
pip install -r requirements.txt
python -m pytest -q                                   # เทสต์เทียบกับเฉลย
python -m auditconcierge samples/tg_company --out ../web/public/data

# (ถ้าต้องการสร้างเอกสารตัวอย่างใหม่: ต้องมีฟอนต์ fonts-tlwg-loma-otf)
python samples/generate.py

# 2) เว็บ
cd ../web && npm install && npm run dev               # http://localhost:5173

# 3) Worker (ถามตอบ) — อีกหน้าต่างหนึ่ง
cd ../worker && npm install && npm test
npm run dev                                           # http://localhost:8787 (build เว็บให้เอง แล้วเสิร์ฟทั้งเว็บและ /api/ask)
```

ถ้าไม่ได้ตั้ง `GEMINI_API_KEY` ช่องถามตอบยังใช้ได้ โดยตอบด้วยการค้นคำจากรายการที่ควรตรวจแทน

## เดโมฟรี (Cloudflare Workers free plan)

```bash
# รันที่ root ของ repo (ไฟล์ตั้งค่าคือ wrangler.jsonc ที่ root, ชื่อ Worker: auditpal)
npx wrangler login
npx wrangler secret put GEMINI_API_KEY    # key จาก Google AI Studio (free tier) เก็บไว้ที่ Worker เท่านั้น
npx wrangler deploy                       # build เว็บ (web/dist) ให้เองก่อน แล้ว deploy ทั้งเว็บและ API เป็น Worker เดียว
```

- ถ้าเชื่อม repo กับ Cloudflare (Workers Builds): ตั้ง Root directory เป็น `/` และ Deploy command เป็น `npx wrangler deploy` ไม่ต้องใส่ Build command เพราะ `wrangler.jsonc` สั่ง build ให้แล้ว
- **ห้ามอัปโหลดโฟลเดอร์ `web/` ตรงๆ** (เช่นลากไฟล์ขึ้น dashboard) เพราะเป็นซอร์สที่ยังไม่ build เบราว์เซอร์จะเปิด `.tsx` ไม่ได้และขึ้นจอขาว ถ้าจะอัปโหลดเอง ให้ใช้ `web/dist` หลังรัน `npm run build` ใน `web/`

- โมเดลถามตอบตั้งไว้ที่ `GEMINI_MODELS` ใน `wrangler.jsonc` เป็นรายชื่อเรียงลำดับ คั่นด้วยจุลภาค ตอนนี้เริ่มที่ Gemma 4 26B → Gemma 4 31B → Gemini 3.5/3.1 Flash-Lite → Gemini 3.8 Flash → Gemini 2.5 Flash ถ้าโมเดลไหนโควตาเต็ม (429), เกินขนาด token, ไม่มีให้ใช้ (404), ล่ม หรือช้าเกิน 20 วินาที Worker จะลองตัวถัดไปเอง และพักโมเดลที่เต็มไว้ 1 นาที ใช้ key เดิมทั้งหมด คำตอบจะบอกว่าตอบโดยโมเดลไหน
- จำกัดการถามต่อ IP ต่อวัน (`DAILY_LIMIT_PER_IP`, ค่าเริ่มต้น 20) และรวมทั้งวัน (`DAILY_LIMIT_TOTAL`, 300) ใน `wrangler.jsonc` ที่ root
- ถ้าต้องการให้ limit แม่นทุก instance ให้ผูก KV namespace ชื่อ `RATE` (ฟรี) ไม่ผูกก็ใช้ได้แต่จะนับแยกตาม instance
- หรือเผยแพร่เฉพาะ `web/dist` บน GitHub Pages / Cloudflare Pages ก็ได้ (ไม่มีช่องถามตอบ)

## Audit Trail (D1, ฟรี)

การตัดสินของผู้สอบบัญชีเก็บที่ Worker ในฐานข้อมูล Cloudflare D1 ชื่อ `auditpal-trail` (binding `AUDIT_DB`, สร้างไว้แล้วใน APAC และใส่ id ไว้ใน `wrangler.jsonc` แล้ว)
deploy ครั้งถัดไปใช้ได้ทันที Worker สร้างตารางให้เองตอนใช้ครั้งแรก ไม่ต้องรัน migration

| ส่วน | ทำอะไร |
| --- | --- |
| `GET /api/trail?ws=&run=` | คืนประวัติทั้งหมด สถานะปัจจุบันที่ได้จากการเล่นประวัติซ้ำ และ `chain_ok` |
| `POST /api/trail` | เพิ่มเหตุการณ์ 1 รายการ: `prepare` (ผล + เหตุผล ≥ 5 ตัวอักษร), `review`, `unreview`, `reopen`, `pair` |

- **เพิ่มได้อย่างเดียว:** โค้ดใช้แค่ `INSERT` และ trigger ใน SQLite ปฏิเสธ `UPDATE`/`DELETE` ทุกครั้ง การกด "แก้ไข" คือการเพิ่มเหตุการณ์ `reopen` ประวัติเดิมยังอยู่
- **สายแฮช:** แต่ละแถวเก็บ SHA-256 ของแถวก่อนหน้า ถ้ามีคนแก้แถวตรงๆ (เช่นผ่าน dashboard) `chain_ok` จะเป็น false และหน้าเว็บขึ้นเตือน
- **server เป็นผู้ตัดสิน:** เวลาบันทึกมาจาก server, ผู้สอบทานต้องไม่ใช่ผู้จัดทำ, ต้องลงนามผู้จัดทำก่อนสอบทาน, รายการต้องมีอยู่ใน `conflict_map.json` รอบเดียวกัน (`run_id`)
- **อ้างหลักฐาน:** server คัดลอก doc / file / locator / SHA-256 ของไฟล์จากผลการตรวจที่เผยแพร่ ไม่รับจากเบราว์เซอร์
- **เดโมปลอดภัย:** ไม่มีอัปโหลด, body ≤ 2 KB, จำกัดการเขียนต่อ IP ต่อวัน (`TRAIL_WRITES_PER_IP`, 200), แต่ละเบราว์เซอร์ได้ workspace ของตัวเอง ถ้าต้องการให้ผู้จัดทำกับผู้สอบทานเห็นชุดเดียวกัน เปิดลิงก์ `?ws=<ชื่อ>` เดียวกัน (ตัวพิมพ์เล็ก ตัวเลข `-` ยาว 4–40)
- ปุ่ม **Audit Trail** บนแถบบน export ประวัติทั้งหมดเป็น CSV พร้อมแฮช
- ถ้าไม่ได้ผูก D1 (เช่นรัน `npm run dev` ของเว็บอย่างเดียว) หน้าเว็บจะเก็บประวัติแบบเดียวกันในเบราว์เซอร์แทนและบอกไว้ใต้ช่องลงนาม

ถ้าจะสร้างฐานข้อมูลใหม่เอง (เช่นบัญชี Cloudflare อื่น): `npx wrangler d1 create auditpal-trail --location apac` แล้วใส่ id ที่ได้ใน `wrangler.jsonc`
ดูข้อมูลได้ด้วย `npx wrangler d1 execute auditpal-trail --remote --command "SELECT seq, at, actor, action, target, value FROM trail_events ORDER BY at DESC LIMIT 20"`
รันในเครื่อง `npm run dev` ใน `worker/` ใช้ D1 จำลองในเครื่อง (`.wrangler/`) ไม่แตะฐานข้อมูลจริง

## ข้อจำกัดของ MVP

- การอ่านเอกสารใช้ **template + regex** ที่ตรงกับเอกสารตัวอย่าง ยังไม่ได้ใช้ LLM สกัดข้อมูล เอกสารรูปแบบอื่นต้องเพิ่ม template
- TEXT_CONFLICT ตรวจด้วยโค้ดเฉพาะเงื่อนไขเครดิต (วัน) ยังไม่มีเส้นทาง LLM เทียบข้อความสัญญาทั่วไป
- Audit Trail ยังไม่มี login: ชื่อย่อผู้ลงนามเป็นสิ่งที่ผู้ใช้พิมพ์เอง (บันทึกตามที่พิมพ์) และการยืนยันคู่ยังไม่รันตรวจใหม่
- Gemini ใช้ได้กับ **ข้อมูลสมมติเท่านั้น** ต้องเปลี่ยนผู้ให้บริการ/สัญญาข้อมูลก่อน pilot กับข้อมูลจริง และใช้ cloud region ในไทยตามที่ออกแบบไว้
- ยังไม่มีระบบ login / สิทธิ์ / การแยกข้อมูลต่อลูกค้า / การลบไฟล์ดิบหลัง 90 วัน (อยู่ในเอกสารออกแบบ ยังไม่ทำใน MVP)
- ผล OCR ขึ้นกับเวอร์ชัน Tesseract (ทดสอบกับ 5.3.4) ไฟล์สแกนตัวอย่างอ่านเลขที่ Invoice ผิดโดยตั้งใจให้เห็นว่าระบบรับมืออย่างไร
