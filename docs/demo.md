# คู่มือทดลองใช้ (Demo) สำหรับผู้ใช้ภายนอก

เว็บเดโม: https://auditpal.foo30749.workers.dev

ทุกอย่างในเดโมเป็น **ข้อมูลสมมติ** (บริษัท สยามออโต้พาร์ท จำกัด ชุดเอกสาร `pipeline/samples/tg_company`) ห้ามอัปโหลดข้อมูลลูกค้าจริง

## บัญชีทดลอง

| บทบาท | อีเมล | ทำอะไรได้ |
| --- | --- | --- |
| ผู้จัดทำ (Preparer) | `preparer@demo.example.com` | อัปโหลด ประมวลผล ยืนยันคู่เอกสาร ลงนามผู้จัดทำ |
| ผู้สอบทาน (Reviewer) | `reviewer@demo.example.com` | ทุกอย่างของผู้จัดทำ + ลงนามสอบทาน (ต้องไม่ใช่คนที่จัดทำรายการนั้น) |
| Manager | `manager@demo.example.com` | ทุกอย่าง + จัดทีม ตั้ง tolerance/materiality ปิดงาน |

รหัสผ่าน **ไม่อยู่ใน repo นี้** ผู้ดูแลระบบสร้างและแจกให้ผู้ทดลองโดยตรง บัญชีทดลองใช้ร่วมกันได้หลายคน จึงเปลี่ยนรหัสผ่านเองไม่ได้
(อีเมลโดเมน `example.com` เป็นโดเมนสำหรับตัวอย่าง ไม่มีใครรับเมลจริง)

## สำหรับผู้ดูแลระบบ: เตรียมเดโม

1. ล็อกอินด้วยบัญชีผู้ดูแลระบบ → **ผู้ใช้** → กล่อง **บัญชีทดลองสำหรับ demo** → กด **สร้าง / รีเซ็ตบัญชีทดลอง**
2. ระบบจะ
   - สร้างบัญชีทั้ง 3 (ถ้ามีอยู่แล้วจะตั้งรหัสใหม่และ sign out ทุกคนที่ใช้รหัสเดิม)
   - สร้าง Engagement "บริษัท สยามออโต้พาร์ท จำกัด" (ข้อมูลสมมติ) ใส่ 3 บัญชีเข้าทีมตามบทบาท
   - อัปโหลดเอกสารตัวอย่าง 20 ไฟล์ แล้วสั่งประมวลผล (เครื่องประมวลผลบน Render อาจใช้เวลาตื่นราว 1 นาที)
3. คัดลอกอีเมล/รหัสผ่านที่ขึ้นมา (แสดงครั้งเดียว) ส่งให้ผู้ทดลอง
4. หลังงานเดโม ให้กดอีกครั้งเพื่อเปลี่ยนรหัส หรือปิดใช้งานบัญชีทดลองจากรายชื่อผู้ใช้
5. ถ้าผู้ทดลองลบไฟล์หรือปิดงาน กดปุ่มเดิมอีกครั้ง ระบบจะเติมไฟล์ที่หายหรือสร้าง Engagement ใหม่ให้

## เส้นทางทดลอง (ประมาณ 10 นาที)

1. **ผู้จัดทำ** ล็อกอิน → เปิด Engagement บริษัท สยามออโต้พาร์ท จำกัด → ดูรายการเอกสาร 20 ไฟล์ (Invoice, PO, ใบรับของ, Bank Statement, สัญญา, นโยบายจัดซื้อ, `remember.json` กฎของบริษัท)
   ถ้ายังไม่มีผลการตรวจ กด **ประมวลผล**
2. ดูรายการจุดที่ควรตรวจ ตัวอย่างที่ควรเจอ
   - PO 120,000 ฿ อนุมัติโดย Purchasing Officer แต่นโยบายกำหนดให้ Manager อนุมัติเมื่อเกิน 100,000 ฿
   - PO 120,000 ฿ แต่ Invoice INV-TG-102 150,000 ฿
   - สัญญาเครดิต 60 วัน แต่ Invoice ระบุ 30 วัน
   - จ่ายเงินก่อนวันที่ของ Invoice, โอนเข้าบัญชีที่ไม่อยู่ใน Vendor master, Invoice ซ้ำ (ไฟล์สแกน), Invoice ไม่มี PO อ้างถึง
3. คลิกแต่ละจุด → ดูเหตุผลและข้อความที่ยกมาจากเอกสาร (กรอบ ✓ บนภาพเอกสารต้นฉบับ) เลขบัญชีธนาคารแสดงแบบปิดบังเท่านั้น
4. ลองถามในช่อง **ถามจากผลการตรวจ** เช่น "รายการไหนจ่ายเงินก่อนได้ Invoice" (AI ตอบจากผลการตรวจและอ้างจุดที่เกี่ยวข้อง)
5. ดู **รอจับคู่**: คู่เอกสารที่ระบบไม่แน่ใจ ผู้จัดทำยืนยันเองได้
6. ผู้จัดทำกด **ลงนามกระดาษทำการ** ในฐานะผู้จัดทำ
7. ล็อกเอาต์ → **ผู้สอบทาน** ล็อกอิน → ลงนามสอบทานรายการที่ผู้จัดทำลงไว้ (ลองลงนามรายการที่ตัวเองจัดทำ ระบบจะไม่ยอม)
8. **Manager** ล็อกอิน → ดู Audit Trail และบันทึกการใช้งาน (ใคร ทำอะไร เมื่อไร เพิ่มได้อย่างเดียว) และกด **Export Excel**
   *ไม่ต้องกดปิดงานในเดโม* ถ้าปิดแล้ว Engagement จะแก้ไขไม่ได้ (ผู้ดูแลกดเตรียมเดโมใหม่ได้)

## ข้อควรรู้

- หลายคนใช้บัญชีเดียวกันพร้อมกันได้ ทุกการลงนามจะบันทึกเป็นชื่อย่อของบัญชี (DP, DR, DM) ไม่ใช่ตัวบุคคล
- ล็อกอินผิด 8 ครั้งใน 15 นาที บัญชีนั้นถูกพัก 15 นาที (ทุกคนที่ใช้บัญชีเดียวกันโดนด้วย)
- โควตาถาม AI ต่อวันจำกัด (`DAILY_LIMIT_PER_IP`, `DAILY_LIMIT_TOTAL` ใน `wrangler.jsonc`)
- เอกสารตัวอย่างดาวน์โหลดได้ที่ `/demo/tg_company/` บนเว็บเดโม (ไม่รวม `expected.json` ที่เป็นเฉลยของชุดทดสอบ)

## โหมดเดโมแบบกดเข้าเลย (DEMO_MODE)

ถ้าไม่อยากแจกรหัสผ่าน ให้เปิดปุ่ม "เข้าโหมดเดโม" บนหน้าเข้าสู่ระบบ

- ตั้งตัวแปร `DEMO_MODE` = `true` ที่ Cloudflare (Workers & Pages → Worker → Settings → Variables and Secrets → Add → Type: Text) แล้ว Deploy
  ไม่ตั้งหรือตั้งเป็นอย่างอื่น = ปิด หน้าเข้าสู่ระบบปกติทำงานเหมือนเดิม
- ใช้ได้เฉพาะเมื่อ `ALLOW_REAL_DATA` ไม่เป็น `true` (ถ้าเปิดข้อมูลจริง ปุ่มและ endpoint จะปิดเอง)
- หน้า login แสดงปุ่มเลือกมุมมอง (ผู้จัดทำ / ผู้สอบทาน / Manager) กดแล้วเข้าด้วยบัญชี `{preparer,reviewer,manager}@demo.example.com` ตามที่เลือก ไม่ต้องกรอกอะไร บัญชีเดโมไม่มีรหัสผ่านที่ใช้พิมพ์เข้าได้ เข้าได้ทางปุ่มนี้เท่านั้น
- ขอบเขต: เห็นและแก้ได้เฉพาะ Engagement สมมติของเดโม (อัปโหลด ประมวลผล ดูประเด็น ถามตอบ ลงนาม) ไม่เห็นรายชื่อผู้ใช้จริง/Engagement จริง
  เปลี่ยนทีม ปิดงาน เปลี่ยนรหัสผ่าน หรือจัดการบัญชีไม่ได้ ไฟล์ละไม่เกิน 3 MB รวมไม่เกิน 30 ไฟล์
- แบนเนอร์ "โหมดเดโม" มีปุ่มสลับบทบาท (ผู้จัดทำ/ผู้สอบทาน/Manager ซึ่งจำเป็นเพราะการสอบทานต้องเป็นคนละคนกับผู้จัดทำ) และปุ่ม "รีเซ็ตเดโม"
  ที่ลบไฟล์และผลทั้งหมดของ Engagement เดโมแล้วเริ่มใหม่ (Audit Trail ที่ลงนามแล้วยังอยู่ตามหลัก append-only)
- ทุกคนที่เข้าเดโมใช้ Engagement เดียวกัน อย่าอัปโหลดข้อมูลจริง

### ไฟล์ CSV ที่ระบบอ่านได้

ระบบดูจากหัวคอลัมน์แถวแรก (ไม่สนตัวพิมพ์เล็ก/ใหญ่และช่องว่าง) รองรับ UTF-8 (มี BOM ได้) และ Windows-874

| ชนิด | คอลัมน์ที่ต้องมี |
| --- | --- |
| ใบสั่งซื้อ (ERP export) | `po_no, po_date, vendor_code, vendor_name, description, amount_excl_vat, approved_by, approver_role` |
| รายการเดินบัญชี | `date, description, withdrawal, counterparty_account` |
| Vendor master | `vendor_code, name_th, name_en, tax_id, bank_account` |

ไฟล์ที่ไม่ตรงรูปแบบจะถูกแสดงในหน้าผลพร้อมเหตุผลรายไฟล์ (ไม่ใช่หน้าว่างเฉยๆ) ตัวอย่างอยู่ที่ `pipeline/samples/tg_company/*.csv`
